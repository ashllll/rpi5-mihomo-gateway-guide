# 网关-安装中断后漂移校验阻塞

> **触发**：升级复制失败后重试报 installed drift；首次安装中断残留脚本；恢复覆盖人工改动。
> **验证**：公开 CLI 在临时根目录注入复制失败、SIGKILL 和人工编辑，核对文件内容、权限、安装清单及 pending，而不只看退出码。

## 首选

`python3 tools/check_release_integrity.py && python3 tools/check_automation.py`

## 被挡时

- 日志或快照损坏、文件不属于 old/new 时保留 pending 与现场；不要重生成清单或手工 record 强行纳管。
- 用无特权 `GATEWAY_ROOT` 沙箱复现；服务和断电问题另做实机验收，禁止在生产注入故障。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 先覆盖文件，最后才记安装清单 | 中间失败形成新旧混合，下一次漂移检查拒绝 |
| 递归创建父目录后写回旧 journal | 覆盖递归新增条目，回滚遗漏父目录 |
| 删除新目录后才清临时文件 | SIGKILL 残留临时文件导致 rmdir 失败 |
| 恢复只做一次预检 | 后续人工改动可能被过期观测覆盖；逐次检查并最终回读 |
| 缺哈希字段当作无需比较 | 损坏记录会把人工文件误认成候选 |
| mkdir 后 chmod 不记录中间状态 | umask/setgid 造成可观察中间态，重试误报冲突 |

## 注意

- 旧字节和权限先持久保存；文件原子替换，pending 原子退役后再清快照。
- 既存敏感目录只收紧 mode，保留 owner/group；失败恢复旧 mode。
- 文件提交与 systemd 操作分开；没有 pending 不能推断“已提交”或“已恢复”。

证据：`tools/check_release_integrity.py` 的 14 项 CLI 回归；本地 `pr11-fixes-20261029` 的红绿日志和独立审查报告。
