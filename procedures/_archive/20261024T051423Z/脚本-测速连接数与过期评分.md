# 原生检测预算与路由策略

> **触发**：重复健康检测、共享预算、原生 URLTest 准入拒绝、账户映射变更或历史账本核对。
> **范围**：离线源码/合成回归，不代表设备已部署；不要用真实节点、公网检测或线上 timer 验证。

## 检查顺序

```sh
python3 tools/check_overlay.py
python3 tools/check_measurement_policy.py
python3 tools/check_native_budget.py
python3 tools/check_stability.py
python3 tools/check_subscription_candidate.py
```

生成清单默认 `measurement.enabled: false`。只有明确授权账户并配置固定核心预算补丁和本地 broker 后，才能生成原生自动检测。下载组使用已授权的扁平叶节点；AI、视频和 TW Fixed IP 保留各自的原生策略。

## 账本约束

- 每个原生 URLTest 检测由核心在拨号前固定预扣 2 次尝试额度，失败与失联不退款。
- 使用 `/var/lib/mihomo-measurements/quality-budget.json` 和 `quality_attempts_per_hour`；保留现有账户键与未过期历史，不清空或迁移到新账本。
- 额度锁内重读当前配置与策略，锁中不调用 HTTP RPC；期限到或文件校验失败则拒绝检测。
- 只接受已映射的明确叶节点和地址/端口，不接受组名、未知账户或拨号链。预算服务不可用只跳过原生检测，不改业务路由和健康历史。
- 同一轻量 URL、期望状态和周期的组共用一个检查所有者，避免业务组重复探测。

## 不要绕过

不要把额度拒绝写成节点故障，不要删除旧账本来“修复”额度，不要把业务健康与平台播放混为一谈，也不要让订阅中的 AI/X/NF 节点绕过下载白名单。过程只记录可验证的离线结果；所有实网部署、timer 和系统服务操作需要另有明确授权。
