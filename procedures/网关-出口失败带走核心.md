# 网关-出口失败带走核心

> **触发**：更新后整网断线；出口探测失败；ExecStartPost 失败；代理恢复后网络突然恢复。
> **验证**：代理不可达时核心 PID 稳定、下游国内 HTTP 和 UDP/TCP DNS 可用；代理恢复无需重启；真实手机通知另验。

## 首选

`python3 tools/check_gateway_resilience.py && python3 tools/check_dns_resilience.py`

把启动门禁限定为进程和本地转发结构。出口探测单独记 degraded 并告警。部署前在独立 Linux 网络命名空间，以真实核心、生产等价的 DNS 路径和防绕行规则验证下游流量。

## 被挡时

- 无法故障注入生产时，用隔离网络验证断代理，再从真实客户端验证正常路径；分别记录证据。
- 线上脚本比仓库新时，以现场备份做最小补丁，不能整文件回退到旧仓库版本。

## 别再来

| 弯路 | 为什么不通 |
|---|---|
| 把外部 204 当成核心启动条件 | ExecStartPost 非零使 systemd 杀掉核心，防绕行规则连国内流量也一起阻断 |
| 用本机 MosDNS 正常证明 VLAN DNS 正常 | VLAN dnsmasq 可能直接接核心 DNS，必须按实际路径验收 |
| 通知发送前记冷却，或把冷却抑制返回当成功 | 投递失败不再重试；恢复后新故障被错误确认 |

## 注意

- 国内域名可能也返回 fake-IP；真实客户端 DNS 验收须连同后续访问，不能只看地址类别。
- 只读观测不消费通知边沿；启动后旧出口缓存必须失效。
- 回滚重启失败必须报告恢复失败，不能吞掉返回值。
