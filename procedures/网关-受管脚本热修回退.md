# 网关-受管脚本热修回退

> **触发**：`/usr/local/sbin/` 下受管脚本被现场 `vim` 热修，manifest 哈希对不上；下次 `install.sh` 会静默覆盖。
> **验证**：`sha256sum` 与 `automation/release-manifest.json` 的 target 哈希一致；`python3 tools/check_overlay_drift.py` 绿。

## 首选

```sh
sha256sum /usr/local/sbin/mihomo-policy-overlay
grep -A1 '"target": "/usr/local/sbin/mihomo-policy-overlay"' automation/release-manifest.json
python3 tools/check_overlay_drift.py
```

回退前先留 `mihomo-policy-overlay.bak-<日期>`；用 manifest 版本覆盖后跑一次订阅更新，确认 `GitHub Control` 组类型等于仓库默认。

## 被挡时

热修改的是仓库还没发布的行为：不要把它留在 live。要么走正常提交进 release，要么回退；两者只能选一个，并写进 procedures。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 直接改 live 当修复 | 下一次 install/订阅更新会静默覆盖，漂移不可复现 |
| 只比对文件存在，不比哈希 | 旧副本、备份、热修版三者会混 |
| 回退后不复跑订阅更新 | 运行配置仍是热修改生成的，GitHub 组类型可能相反 |

## 注意

- 2026-10-31 的 overlay 热修（GitHub Control `fallback`→`url-test`、删 media 调用）目标已不成立：git-transport 已走 GitHub Download；按 manifest 回退，`.bak-20261031` 留证。
- 回退是第 3 阶段实机动作；仓库侧只保证 release 脚本与 manifest 一致。设备上先 `python3 tools/check_overlay_drift.py --live /usr/local/sbin/mihomo-policy-overlay --backup /usr/local/sbin/mihomo-policy-overlay.bak-20261031`；本地用记录的漂移副本做过红/绿演示。
