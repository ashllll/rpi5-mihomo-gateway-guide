02工作原理

一句话：WAN 进来 → Traffic Flow Engine 做防火墙 / IPS / DPI / 策略路由 → 分发到 LAN/VLAN；同时 UniFi OS 上的 Network 应用负责配置与遥测，Cloud Connector 负责「出站反向长连接」，让云端不穿透也能管理。

① 转发面（数据流）

数据包从 WAN 口进入，经 Zone-Based Firewall、IPS/IDS（55,000+ 签名）、DPI、应用识别，按策略路由 / QoS / 多 WAN 负载均衡后从 LAN 口或 VLAN 出去。

② 控制面（配置）

UniFi OS 承载 Network / Protect 等应用；本地 UI 与 Local API 直连 https://consoleIP；云端经 Site Manager 下发或经 Cloud Connector 代理。

③ 存储面（可选）

NVMe（≤2 TB）走 PCIe Gen3×2，供 Protect 存录像；无 SSD 的版本不影响路由转发，只是不能本地录像。

04API 链路

两套 API、两把 key，互相不可互换：云侧 Site Manager（api.ui.com，官方标注只读）与 本地 console（https://consoleIP/proxy/network/integration，可读写）。

认证方式

HTTP 头 X-API-Key（llms.txt 写作 X-API-KEY，头名大小写不敏感）。密钥在 unifi.ui.com/settings/api-keys 生成，只显示一次；可设 1/3/6/12 个月有效期。

Scope：Site Manager（跨站概览）与 UniFi Applications（Network / Protect / InnerSpace）分开勾选。

两个入口

云：https://api.ui.com/v1/...，控制台数据走 /v1/connector/consoles/{consoleId}/proxy/network/integration/...

本地：https://{consoleIP}/proxy/network/integration/v1/...（需本地签发的 key）

完整规范：Network 44 路径 / 73 操作；Site Manager 10 路径 / 14 操作。

分页与过滤

Network：offset/limit，默认 25，上限 200（热点券例外 100/1000）；响应包裹 {count,data,limit,offset,totalCount}。

Site Manager：pageSize + nextToken，单页 ≤500；响应 {data,httpStatusCode,traceId,nextToken}。

filter 语法：property.function(args)，支持 and/or/not、like/in/eq/gt/le 等；可过滤属性写在每个 operation 的 description 表里。

限流与超时

Site Manager：稳定版 10,000 请求/分钟；EA 100/分钟；超限 429 + Retry-After。

Cloud Connector：每个 console 100 请求/分钟；单请求超时 25 秒；响应体上限 10 MB；console 固件需 ≥ 5.0.3。

Network 本地 API：官方未公布限流数值。

错误体两种形状
  • Network：7 字段 code / message / requestId / requestPath / statusCode / statusName / timestamp
  • Site Manager：4 字段 code / httpStatusCode / message / traceId，含 RATE_LIMIT

05实测记录（2026-10-31）

在同一台 UCG Max 上验证「云侧 key 与本地 key 不可互换」及分页/过滤行为（MAC、IP、UUID 已脱敏）。

本地 key ✅

GET https://192.168.0.1/proxy/network/integration/v1/info → 200 {"applicationVersion":"10.6.109"}

云侧 key 直连本地 ❌

同一请求 → 401；云侧 key 只能走 api.ui.com 的 Connector 代理。

Connector 路径 ✅

/v1/hosts → reportedState.name = "Cloud Gateway Max"；代理到 /v1/info 同样是 10.6.109。

关键行为
  • filter=state.eq('ONLINE') 命中 UCG Max（固件 5.1.33）与 U7 Lite；非法 filter 返回 400，错误体 7 字段与文档一致。
  • limit=500 被服务端夹到 200；clients 的 totalCount 为 26。
  • statistics/latest 返回 CPU 36.2% / 内存 69.6% / 启动时长等字段。
  • 响应头未见 x-ratelimit-*；429 与写操作尚未实测（报告已列为未验证项）。
