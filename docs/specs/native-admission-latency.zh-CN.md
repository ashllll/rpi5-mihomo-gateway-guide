# 原生探测准入时延契约

原生 URLTest 向本机 broker 请求准入，socket 总时限为 1 秒；请求携带的探测截止时间可为 5 秒。只有准入成功后，核心才连接节点并更新健康历史。准入超时不能等同于节点检测失败，也不能用分组初始 `alive` 代替已完成的检测记录。

修复通过一次 JSON 编码和精确字节校验缓存减少 CPU 开销。每次仍在账本 flock 内读取全部文件；仅当规范路径及全部字节与上次成功持久化的快照一致时复用已校验结果，并复制待修改的映射。外部写入或损坏导致缓存不命中，执行完整校验；两个 fsync 都完成后才发布新快照。

账户匹配、无额度模式下的计数、完整账本校验、跨进程账本锁、策略与截止时间复核、文件及目录 fsync、原子替换均保持。不得以跳过预扣、放宽核心时限或关闭校验实现提速。健康探测周期、角色池和路由规则不属于此修复。

首次输入解析优先使用 PyYAML 的 `CSafeLoader`，缺少 libyaml 时退回 `SafeLoader`；两者都禁止 Python 对象构造。性能验收必须覆盖实际部署的解析器及配置规模，不能只用匿名小配置推断首次加载时延。

验收通过 broker 的 Unix socket 接口执行：在目标 CPU 和文件系统上，用匿名的 2400 条既有记录及 70 个并发请求，分别验证冷输入和预热输入；每个请求必须在 1 秒内获得允许，原记录完整保留，新增扣费合计为 140。负载参数可显式调整，以复核不同部署规模。该检查不访问公网、不连接生产 socket，也不写生产账本。

```sh
python3 tools/check_native_admission_load.py
python3 tools/check_native_budget.py
python3 tools/check_measurement_policy.py
```

负载检查是目标机器的性能验收，不纳入跨平台单元测试时间门槛。软件回归还须覆盖账本损坏、额度限制、策略变更、锁等待和请求截止时间。上线后需核对当前配置对应的 provider 健康历史，以及实际客户端的国内、AI、GitHub、视频路径；单次探测成功不代表持续传输稳定。
