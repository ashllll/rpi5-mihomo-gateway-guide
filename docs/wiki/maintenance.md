# Wiki 维护与变更交付

[Wiki 首页](../README.md) · [ADR 索引](../adr/README.md) · [验证矩阵](validation.md)

## 每类信息放在哪里

| 信息 | 归属 |
|---|---|
| 项目价值、最短入口 | 根 README |
| 完整阅读路径与所有文档入口 | docs/README.md |
| 当前机制与操作 | docs/wiki/ 专题页，链接源码和已有详细指南 |
| 高成本取舍与理由 | docs/adr/，改变时新增替代记录 |
| 明确的项目领域词义 | 根 GLOSSARY.md，不放部署细节 |
| 早期记录、一次性调查 | 保持原档案并标日期，不冒充当前运行说明 |
| 真实账号、节点、网络清单及日志 | 私有部署记录，不进入公开 Wiki |

不要复制整份源码参数表到多个文档。公共默认值以源码/模板为准；现场实际值以私有配置为准。
给入口、状态、配置和测试分别链接即可，避免把一份 Wiki 再变成第二套配置。

## 修改时的最小闭环

1. 记录实际检出提交与已有改动，阅读当前逻辑及调用方。
2. 根据改动更新对应机制说明、配置参考和验收边界；新增页面接入 Wiki 首页。
3. 只有架构取舍改变时新增 ADR；记录的日期不冒充原始讨论日期。
4. 验证相对链接、引用文件、Markdown 结构与隐私；运行受影响的回归。
5. 区分本地完成、已提交、远端发布、已部署和真实用户验收，分别给证据。

本 Wiki 不要求自动发布网站，也不会因为改文档而重启设备、安装依赖或创建外部任务。
提交、推送、部署和写盘都需要对应授权；没有远端回读证据时不写“已发布”。

## 源码变化的联动表

| 变化 | 同步页面 | 必要验证 |
|---|---|---|
| 新入口/运行目录/安装行为 | 入门、参考、运维 | dry-run、重复安装、恢复边界 |
| env 或 manifest 字段 | 配置参考、自动化说明 | 参数传播、既有数据保留 |
| 节点规则或能力池 | 架构、智能选择，必要时 ADR | 空池拒绝、能力约束、规则顺序 |
| 探针状态与恢复动作 | 运维、验证 | 假阳性/限制/超时、不中断其他业务 |
| 控制面/防火墙暴露 | 安全、ADR | LAN/WAN/容器及真实透明入口 |
| 新测试/CI | 验证矩阵 | 实际运行结果，标明平台与权限 |

## 证据记录模板

```text
日期/源码提交/部署路径：
变更范围和未改动范围：
源码与配置依据（脱敏）：
执行的命令、平台与结果摘要：
证据层（静态/模拟/隔离核心/显式代理/真实LAN/真实业务）：
未执行项、已知限制、业务影响：
备份位置及经核对的回滚办法（私有记录）：
是否提交/远端回读/部署/用户验收：
```

文档不是持续监控系统。现场验证过一次的事实必须带日期，不能长期显示成当前健康状态。
