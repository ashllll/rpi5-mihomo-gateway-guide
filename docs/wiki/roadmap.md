## 建议按收益推进

| 优先级 | 提议 | 需要的证据 | 推进前门禁 |
|---|---|---|---|
| 1 | 业务可用性历史与归因 | 按业务记录失败、出口、样本年龄、限制状态，脱敏保存 | 存储/保留周期与隐私方案，不采集账号请求内容 |
| 1 | 真实客户端验收基线 | 手机 X 时间线、视频、AI 流式连接、UDP 与重启 | 独立管理通道、授权样本、回滚演练 |
| 2 | 多路径候选资格 | 节点 API 正常但 CDN 失败时，备用节点是否真正改善 | 影子比较、最低候选数、探测预算及无可用节点保底 |
| 2 | 会话稳定优先的选路 | 抖动、成功率、出口切换次数与实际中断 | 保持时间/收益阈值可配置，故障时有明确退出策略 |
| 3 | 扩展下载样本与收益验证 | 现有受限采样与真实下载体验的相关性 | 供应商许可、总流量/并发上限，不用大模型测速 |
| 3 | IPv6/访客隔离/更强控制平面 | 路由/DNS/透明入口/容器暴露的完整验收 | 单独 ADR、隔离测试环境与兼容性矩阵 |
| 研究 | Landscape + Mihomo | 固定版本源码、隔离硬件的 TProxy/eBPF 证明 | 先走[分阶段验收](../landscape-acceptance.zh-CN.md)，禁止直接接管生产 |

这些提议尚未组成多指标生产调度器。当前不提供机器学习选点、全平台解锁识别、单连接多机场带宽聚合、
无损 TCP 迁移或自动商业套餐能力发现。

## 何时停止“优化”

上游故障、账号风控或源站限速不能靠反复重启解决。没有真实用户收益或无法区分原因时，
先保留正常业务、记录最小脱敏证据，不再叠加调参。
性能改动先有负载基线、一次只改一个变量、验证功耗/温度/吞吐与回退，
不默认启用 BBR、超频、强制性能 governor 或未经测试的内核参数。
