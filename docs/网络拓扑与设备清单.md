## 9. GitHub 下载路由（当前状态）

- 分流规则由 `mihomo-policy-overlay` 从私 manifest `/etc/mihomo/adaptive/capabilities.yaml` 的 `download_quality.profiles` 生成，不是写死在 `/etc/mihomo/config.yaml`；订阅更新后仍保持。
- `git-transport` 组 = `GitHub Download`（机房中转，65 成员），只覆盖 `github.com`；`api.github.com` 与 `alive.github.com` 留在 `GitHub Control`（53 个家宽住宅节点，`fallback`），API 小包对带宽不敏感。
- 瓶颈是**节点带宽**而非选路延迟：`GitHub Control` 实测只有 ~55–75 KB/s，因此这两组的差异不能靠改 `url-test` 弥补，只能把 `github.com` 的数据流换到中转组。
- `codeload.github.com` 等静态下载域名本来就走 `GitHub Download`，因此"tar 包快、clone 慢"的差异即来源于此。
- 实测（NAS 192.168.20.193）：`git clone --depth 1 https://github.com/jqlang/jq` 由 29.19s 降至 2.94 / 3.23 / 3.21s（约 10×），三次稳定。

### 9.1 fnOS 上的 git

fnOS 应用商店的 git（`/var/apps/git/target`，`/usr/local/bin/git` 指向它）编译期把 exec-path 写死为 `/var/packages/git/target/libexec/git-core`，该路径原本不存在，`git clone` 会报 `'remote-https' is not a git command`。

根因修复是一个符号链接（root 执行）：

```sh
mkdir -p /var/packages && ln -sfn /var/apps/git /var/packages/git
```

链接建好后登录 shell 与非登录 shell（cron、`ssh nas 'git …'`、runner）都能正常 clone；`git --exec-path` 解析为 `/var/apps/git/target/libexec/git-core`。`llll` 的 `~/.profile` 与 `~/.bashrc` 里的 `GIT_EXEC_PATH` / `GIT_TEMPLATE_DIR` 保留作兜底（带 `[ -d … ]` 守卫），不再是必需项。

系统自带 `/usr/bin/git`（2.43.0，helper 在 `/usr/lib/git-core`）不受影响。

### 10.1 NAS 上的工作副本

`/vol1/1000/github` 是一份**真实签出的工作副本**（3.8 MB，`origin` = Gitea，非软链）：

```sh
ssh llll@192.168.20.193
cd /vol1/1000/github
git pull            # 需要时同步
git push origin main
```

- 远端形式是 `ssh://gitea@192.168.20.193:2222/llll/rpi5-mihomo-gateway-guide.git`。用户名必须是 **`gitea`**（Gitea 内置 SSH 服务按 `RUN_USER` 校验，写 `git@` 会被拒：`Invalid SSH username git - must use gitea for all git operations via ssh`）。克隆已在本地配置 `core.sshCommand`，日常不必再带参数。
- 免密靠 `llll` 的 `~/.ssh/id_ed25519`（公钥已加到 Gitea 账户），不需要在 NAS 上存密码或 access token。
- **fnOS 的分区权限怪癖**：`/vol1` 上新建文件/目录的权限会跟随父目录（父目录是 `000` 时子项也是 `000`，父目录是 `755` 时新文件也是 `755`），`umask` 与默认 ACL 都不起作用。因此克隆后要做一次整理，并关掉 git 的 mode 检测（否则每个文件都显示 mode 变更）：

```sh
cd /vol1/1000/github
git config core.fileMode false
find . -path ./.git -prune -o -type d -exec chmod 755 {} +
find . -path ./.git -prune -o -type f -exec chmod 644 {} +
chmod 755 scripts/preflight.sh automation/sbin/* ops/mihomo-config-install
```

整理后 `git status` 干净，`./scripts/preflight.sh --staged` 在 NAS 上可直接跑（PyYAML 已具备）。
